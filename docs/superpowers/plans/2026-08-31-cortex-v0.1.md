# Cortex v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the local-first Cortex v0.1 vertical slice: shared notes, tasks, provenance-bearing memories, hybrid search, local agent tools, and authenticated ChatGPT MCP access.

**Architecture:** `cortexd` exclusively owns SQLite and exposes authenticated local IPC. The `brain` CLI and `cortex-mcp-gateway` are adapters over typed commands/queries in `cortex-application`; the gateway is connected through an outbound-only tunnel. Lexical FTS5 and local embeddings are fused deterministically, while policy, optimistic revisions, idempotency, provenance, and audit are enforced in the daemon.

**Tech Stack:** Rust stable (MSRV selected and documented in Task 1), Tokio, Serde, SQLx/SQLite, Clap, tracing, Axum, rustls, Reqwest, RMCP, UUID v7, local OpenAI-compatible inference/embedding server.

**Spec:** `docs/superpowers/specs/2026-08-31-cortex-v0.1-design.md`

## Global Constraints

- Read the approved specification before every task; its invariants are requirements, not suggestions.
- Use TDD: write and run the failing test before the production change for every behavior.
- Use `#![forbid(unsafe_code)]` in every first-party crate unless a documented exception is approved.
- Do not use `unwrap()` or `expect()` in production paths; tests may use them.
- All durable IDs are UUIDv7; every durable record has `WorkspaceId`, `Revision`, timestamps, and lifecycle.
- `cortexd` is the sole SQLite owner and sole final policy decision point.
- All commands carry `operation_id` and expected revision where they mutate an existing entity.
- Every mutation and policy decision writes a redacted audit event in the same transaction.
- Credentials use opaque `SecretRef` values and a platform secret-store adapter; never place a credential in SQLite, audit data, tracing fields, model context, or MCP output.
- MCP, CLI, and local agent invoke the same typed application capabilities; no interface may contain business rules.
- Run `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`, and `cargo test --workspace` before every task commit.
- Keep v0.2+ systems out of implementation: projects, calendar/scheduling, connectors, automation, skills, sync, multi-user operation, vector index, irreversible purge, GUI/TUI, and public inbound serving.
